# Integrate Inlined JuiceFS Data Engine with Metadata Adapter

Bowl requires high-throughput chunk slicing, NVMe staging cache, and S3 batch uploading, while enforcing Connect-RPC thin client access, per-disk PostgreSQL schema isolation (`disk_<uuid>`), and OWMR write lease concurrency. Directly importing the upstream `github.com/juicedata/juicefs` module causes severe build failures due to transitive interface incompatibilities and CGO dependencies, whereas maintaining a fully custom chunk engine increases long-term edge-case bug risks. We decided to integrate a build-stabilized, inlined JuiceFS data engine under `services/storage/internal/juicefs` paired with a custom metadata adapter connecting to Bowl's per-disk PostgreSQL schema tables (`chunks`, `slice_refs`), while scoping S3 object storage keys with `chunks/<disk_id>/`. This leverages JuiceFS's battle-tested chunk slicing and S3 uploading pipeline while preserving pure-Go compile compatibility, per-disk schema isolation, and cascade physical cleanup semantics.
